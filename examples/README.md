# Examples — Worked Sample Outputs

> **Phase 1, illustrative only.** These files show what the StoryNova Narrative OS agents *would* produce. They were hand-authored as a reference set, **not** generated by a live run (there is no deployed engine yet). The competitor "LinearDeck" is fictional and all citations are placeholders showing where verified sources would attach.

## How to read this set

The whole point of the architecture is that all three assets come from **one spine**. Follow the files in order to see that in action:

1. **`01_narrative_schema.json`** — the canonical spine (the single source of truth) for a competitor narrative: StoryNova vs. LinearDeck.
2. **`02_battle_card.md`** — the Battle Card agent's projection of that spine (why we win, landmines, trap questions).
3. **`03_objection_guide.md`** — the Objection agent's projection (Feel–Felt–Found responses, each with a proof point).
4. **`04_pitch_deck.md`** — the Deck agent's slide plan, mapped from the spine's story_arc.

Notice that the positioning line, the three differentiators, and the citations are **identical across all three assets** — that consistency is what the spine guarantees.

## What "real" looks like when live

When the code in `agents/` and `modules/` is wired to real LLM + MCP clients:
- The Research agent pulls live competitor facts and CRM/call data.
- The Narrative agent writes `01_narrative_schema.json` automatically.
- Each generator writes its own artifact.
- The Critic blocks any claim whose citation can't be verified.
- The Deck agent calls the Slides MCP to return a real .pptx / Google Slides URL.
